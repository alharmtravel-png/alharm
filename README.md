# نظام محاسبة السياحة والسفر

تطبيق Next.js متكامل (Frontend + API + قاعدة بيانات Postgres عبر Prisma) لإدارة العملاء والموردين والحجوزات والدفعات متعددة العملات، مع تقارير وتصدير إكسيل/CSV واستيراد حجوزات من ملفات إكسيل.

## التشغيل محليًا

1. `npm install`
2. أنشئ ملف `.env` بناءً على `.env.example` وضع فيه رابط قاعدة بيانات Postgres حقيقية (مثلاً من Neon أو Vercel Postgres).
3. `npx prisma migrate dev --name init` لإنشاء الجداول.
4. `npm run dev` وافتح http://localhost:3000

أول دخول: هتدخل أي كلمة مرور (3 أحرف على الأقل) وهتبقى هي كلمة مرور النظام.

## النشر على Vercel

1. ادفع هذا الكود لمستودع GitHub جديد، واربطه بمشروع Vercel الحالي (Settings → Git → Connect Repository).
2. من تبويب Storage في Vercel: أنشئ قاعدة بيانات Postgres (Neon)، وهيتم إضافة `DATABASE_URL` و`DIRECT_URL` تلقائيًا لمتغيرات البيئة.
3. بعد أول Deploy، شغّل الهجرة لإنشاء الجداول:
   `npx prisma migrate deploy` (من جهازك، بعد تعيين `DATABASE_URL` نفس قيمة Vercel) أو أضف خطوة Build Command: `prisma migrate deploy && next build`.
4. أعد النشر (Redeploy).

## استيراد إكسيل

من تبويب "الحجوزات" → "استيراد إكسيل". الأعمدة المتوقعة في الصف الأول (Header):

| التاريخ | نوع الخدمة | العميل | المورد | قيمة البيع | عملة البيع | قيمة الشراء | عملة الشراء | الحالة | ملاحظات |

- التاريخ بصيغة `yyyy-mm-dd` أو `dd/mm/yyyy`.
- لو اسم العميل/المورد غير موجود، يتم إنشاؤه تلقائيًا.
- الحالة أحد القيم: جديد، مؤكد، مدفوع جزئياً، مدفوع بالكامل، ملغي، مسترجع.

## البنية

- `prisma/schema.prisma` — نموذج البيانات (عملاء، موردين، حجوزات، دفعات، إعدادات، جلسات دخول)
- `app/api/*` — كل عمليات القراءة/الكتابة الفعلية على قاعدة البيانات
- `components/*` — واجهة المستخدم (React) بنفس تصميم النظام الأصلي
